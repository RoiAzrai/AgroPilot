# Calculation decisions

The decisions behind [../SKILL.md](../SKILL.md). The FAO references point to [fao56.md](../../../../services/planner-service/docs/research/fao56.md). Follow these decisions. If one needs to change, change it here first, then in SKILL.md and cases.md.

| Decision | What we chose | Why | Deviation from task / FAO-56 |
| --- | --- | --- | --- |
| Crop coefficient | Single Kc (Table 12, Eq. 66) | Simple and traceable by hand, and the task asks for Kc per day | **Deviation from FAO.** FAO-56 prefers the dual Kcb + Ke approach for high-frequency microirrigation (Ch. 5, Table 10) |
| Partial wetting | No fw correction of Kc_ini (Eq. 60) | Conservative: it can only over-water slightly in the initial stage, never under-water | FAO-56 allows Kc_ini × fw for drip. We don't apply it |
| Depletion fraction (I21) | p from Table 22 (tomato 0.40, pepper 0.30) as the per-crop default, without the `0.04 (5 − ETc)` correction. The optional `DEPLETION_FRACTION_OVERRIDE` (planner-service config, 0..1, unset by default) replaces p for every crop when it is set | Water before stress starts. Total water is similar over a season (irrigation ≈ ETc minus effective rain). Mainly the timing changes | **Deviation from task by default.** The task says "below half". Setting the override to 0.5 gives the task's rule |
| When and how much | Irrigate on the same day the bucket would end below RAW, and refill to full (I = Dr_start + ETc), at most `MAX_DAILY_RUN_MINUTES` a day, the rest on the following days (I23) | Refilling to full comes from Annex 8 (net irrigation = depletion). Same-day irrigation is our choice, based on FAO Ch. 8 ("irrigations should be applied before or at the moment when the readily available soil water is depleted"). It avoids the stress day | Annex 8 irrigates the next morning. We irrigate the same day |
| Daily irrigation (I21) | `DEPLETION_FRACTION_OVERRIDE=0` gives irrigation of ETc every day | A grower who wants daily drip gets it through configuration | None. It is a setting, not code |
| Rain | Ignore rain < 0.2·ET0. No runoff. Rain beyond full drains away | FAO Ch. 8 rule. Annex 8 assumes RO = 0 | FAO-56 gives no "effective rainfall" method |
| Past rain (I16) | In the bucket suggestion, past rain follows the same rule as forecast rain: rain < 0.2·ET0 is ignored | One rule for every day, so a past day and a forecast day with the same weather give the same bucket change | None |
| Bucket floor (I17) | The bucket never goes below empty: depletion is capped at TAW of that day | The soil can't give more water than it holds. The suggestion simulation reaches the cap, because it never irrigates. A plan reaches it when it starts (nearly) empty (`bucket_start` near 0) or when the daily cap (I23) is below that day's ETc | None |
| Efficiency | Net minutes, with no efficiency factor | FAO-56 gives no factor. An invented one would be a hidden constant | None. A future factor would go in config.py |
| Litres (I19) | `litres = I · area_m2`, rounded to whole litres **half up** (e.g. 248.5 → 249), not Python's `round()` (half to even: `round(248.5) == 248`). No case in cases.md is affected (none ends in exactly .5). Implementation: first round x to **6 decimal places** (the named constant), then round half up: `Decimal(repr(round(x, 6))).quantize(Decimal("1"), rounding=ROUND_HALF_UP)`. Not `floor(x + 0.5)`, and not `Decimal` alone, because `Decimal` does not undo a float error already in x: `0.5005 * 1000` is `500.49999999999994` in float, and `Decimal` of it rounds to 500, not 501. Rounding to 6 places first removes the float error (~1e-13), and 6 places are far finer than 1 litre or 1 minute | A grower reads and meters whole litres. Half up is the rounding a grower expects | None |
| Run minutes (I20) | `run_minutes` is computed from the unrounded irrigation depth I, then rounded to whole minutes **half up**, as in I19 (not Python's `round()`). Same implementation note as I19. No case in cases.md is affected | One rounding step keeps both outputs traceable to I. Rounding the litres first would add a second rounding error | None |
| Season end | i > season length → stage `"ended"`, `run_minutes: 0` | No Kc after the late stage, and the crop is harvested | None |
| Before planting (Q4) | i < 1 → stage `"not_planted"`, with the same zeros and nulls as `"ended"` (litres 0, run_minutes 0, kc, bucket_mm and bucket_capacity_mm null) | The registry runs on UTC+14, so for a few hours a plan's first day can come before the planting date. There is no crop yet | None |
| Suggestion after season end (I18) | Season already ended → `suggestion: null`, `reason: "season_ended"` (not a `stage` field) | There is no crop to water, so there is no bucket to suggest | None |
| Output fields | No `need_mm` in the plan | Task FR-2.10 (updated upstream) lists no `need_mm` | None |
| Initial bucket | `bucket_start` in [0, 1], default 1.0. Suggest and confirm from the grower's last irrigation date, with `422` for a future date, a date before planting, more than 92 days ago, or an invalid date | A stateless planner that assumes a full bucket every day postpones irrigation forever | **Deviation from FR-2.3 / FR-2.11, on purpose.** The suggestion needs past ET0 and rain (FR-2.3 gives the forecast from today) and an input beyond plot, soil, emitter and forecast |
| Suggested fraction (I14) | The suggested `bucket_start` is a fraction of **today's** TAW: `1 − Dr / TAW(today)`, clamped to [0, 1] | `bucket_start` is applied on plan day 1 (today) as `Dr_0 = (1 − bucket_start) · TAW(day 1)`, or on the first planted day when day 1 is `"not_planted"`, so both must use the same TAW | None |
| Suggestion input (I15) | `422 VALIDATION` when the last irrigation date is in the future, before planting, more than 92 days ago, or not a valid date, and when `bucket_start` is outside [0, 1]. Irrigation today is valid: no past day to simulate, suggestion 1.0 | 92 days is the most past weather the weather-service serves. A date it can't simulate must be refused, not guessed | None |
| Fewer past days than needed (I22) | **No past days needed:** D = today (I15) or D = yesterday: the simulation D+1 .. yesterday is empty, so the planner requests no past days and the suggestion is 1.0. **Otherwise** the planner requests `past_days = today − D − 1`. weather-service returns only the past days that exist, ending yesterday, plus `past_days_returned` (weather W27). **All returned:** the suggestion as in SKILL.md. **Fewer returned (at least 1):** assume the bucket was full at the **start** of the first returned day, so that day's ET counts. This is the tightest valid optimistic bound. If the optimistic run reaches empty (depletion = TAW of that day) on **any** day, the result is exact: the value of the run (0, or above it if rain fell after that day or the roots are still growing). If it never reaches empty, answer "cannot suggest exactly — enter the bucket level manually". **0 returned** (and D < yesterday): "cannot suggest exactly". The response format of "cannot suggest exactly" is defined in the planner API (stage 4.2) | The daily update never makes a fuller bucket end emptier, so the true depletion is always ≥ the optimistic one. Both are capped at TAW of the day. Once the optimistic run hits the cap, the true one is at the cap too, and from then on the two paths are identical. A run that never hits the cap could hide missing water, so no number is suggested. The weather-service reports facts, and the planner decides what to do with fewer days | The suggestion can be withheld, so the grower enters the level by hand |
| Daily cap (I23) | `MAX_DAILY_RUN_MINUTES` (planner config, default 1440, range 1..1440). `cap_mm = MAX_DAILY_RUN_MINUTES * flow_lph / (row_spacing_m * emitter_spacing_m) / 60`. A refill is irrigated at most `cap_mm` a day and continues on the following days until the bucket is full. The rule is the `refilling` flag in SKILL.md "The bucket". The continuation stops on the first day whose `Dr_start + ETc` (after that day's rain) fits under the cap. Rain on a continuation day lowers the need. A day with stage `"ended"` never irrigates, so the season end stops it. Stateless: the continuation lives inside one plan, and a new request starts from `bucket_start`. `need` is not capped at TAW, only `Dr_end` is (I17). The suggestion is unaffected, because it never irrigates | A day has 1440 minutes. The North block (loam, tomato, TAW 122.5 mm) needs about 1,800 minutes for one refill | **Beyond the task**, which has no cap. It is a setting, not code |
| Future improvement | Store the irrigations in a DB | The planner could then know the real bucket level, with no guess | Not built |
